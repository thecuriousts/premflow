# Plan to Fix search_logs Bug in main.c

## Problem Description
The `search_logs` function in `main.c` calls `get_data_path` twice to get paths for the log file and todo file. However, `get_data_path` uses a static buffer, causing the second call to overwrite the result of the first call. As a result, both `logpath` and `todopath` end up pointing to the same memory location containing the path from the latest call (todo.txt), leading to incorrect search behavior.

## Root Cause
- `get_data_path` function uses `static char path[512];` to store the constructed path.
- When called multiple times, it overwrites the previous path in the same static buffer.
- In `search_logs`, `logpath` gets set to the log file path, but `todopath` overwrites it with the todo file path.
- Both pointers now reference the same buffer containing the todo file path.

## Proposed Fix
1. Modify `search_logs` to use local buffers and copy the paths immediately after calling `get_data_path`.
2. Use `strncpy` to copy the returned path into separate local arrays (`logpath_buf` and `todopath_buf`).
3. Update the `snprintf` calls to use these copied buffers instead of the original pointers.

## Implementation Steps
1. Add two local char arrays in `search_logs`: `char logpath_buf[512];` and `char todopath_buf[512];`.
2. After calling `get_data_path(LOG_FILE)`, copy the result: `strncpy(logpath_buf, get_data_path(LOG_FILE), sizeof(logpath_buf));`.
3. Similarly for todo: `strncpy(todopath_buf, get_data_path(TODO_FILE), sizeof(todopath_buf));`.
4. Replace `logpath` with `logpath_buf` and `todopath` with `todopath_buf` in the `snprintf` calls.

## Alternative Solutions Considered
- Modify `get_data_path` to allocate memory with `malloc` and require callers to `free` it (adds memory management complexity).
- Call `get_data_path` inline in each `snprintf` (but the static buffer issue persists across calls).
- The proposed fix is the simplest and safest for this codebase.

## Testing
After implementing the fix:
