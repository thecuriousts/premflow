# Sound Configuration System for Premflow Pomodoro

## Overview
Add a user-configurable sound system to premflow that allows customization of alert sounds across different operating systems. The system will use a config file in ~/.premflow/config.txt to store sound settings, enabling users to specify their preferred sound player and audio files.

## Goals
- Create flexible sound configuration system
- Support multiple sound types (alarm, completion, notification)
- Enable OS detection and appropriate defaults
- Allow users to customize or disable sounds completely
- Maintain backward compatibility (no sounds if config missing/empty)

## Implementation Plan

### 1. Config File Structure
Create ~/.premflow/config.txt with the following format:
```
# Sound Configuration for premflow
# Lines starting with # are comments
# Empty file = no sounds

# Sound player command (required if using sounds)
PLAYER=paplay

# Individual sound commands for different events
POMO_COMPLETE=paplay /usr/share/sounds/freedesktop/stereo/complete.oga
POMO_START=paplay /usr/share/sounds/freedesktop/stereo/phone-incoming-call.oga
TASK_COMPLETE=paplay /usr/share/sounds/freedesktop/stereo/bell.oga
```

### 2. Code Changes Required

#### A. Add Config Reading Function
- Create `read_config()` function that reads ~/.premflow/config.txt
- Parse key=value pairs, ignoring comments and empty lines
- Store in a struct or use global variables for sound commands

#### B. Modify Pomodoro Function
- Call read_config() at start of pomodoro()
- Execute POMO_START sound if configured
- Execute POMO_COMPLETE sound when timer finishes

#### C. Add Sound Support to Other Functions
- Task completion: use TASK_COMPLETE sound
- Potentially add sounds for journal creation, note saving, etc.

#### D. Remove Hardcoded Sound Command
- Replace current SOUND_CMD macro with dynamic config-based approach
- If config file doesn't exist or PLAYER is empty, skip sounds

### 3. User Configuration Guide
Add a new command: `premflow config sound`
- Opens config file in editor for user customization
- Provides template with common sound options for different OS
- Includes comments explaining each option

### 4. OS-Specific Defaults
Detect OS and provide appropriate default config templates:
- Linux: paplay with freedesktop sounds
- macOS: afplay with system sounds
- Windows: powershell with system sounds
- Fallback: terminal bell

### 5. Error Handling
- Gracefully handle missing config file (no sounds)
- Skip sounds if player command fails
- Log sound execution failures to debug if needed

### 6. Testing
- Test with empty config (no sounds)
- Test with valid config (sounds play)
- Test with invalid config (fallback behavior)
- Test on different OS types

### 7. Documentation Updates
- Update help text to mention sound configuration
- Add examples of common configurations
- Document how to find available system sounds

## Benefits
- User can fully customize their audio experience
- Works across different Linux distributions and desktop environments
- Maintains simplicity for users who don't want sounds
- Extensible for future sound events

## Potential Challenges
- Sound file paths may vary between systems
- Audio subsystem differences (ALSA, PulseAudio, PipeWire)
- Ensuring commands don't block the main program flow
- Handling permission issues for audio access
